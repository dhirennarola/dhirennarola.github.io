# DESIGN — the rules every page follows

Version 3 ("Ledger"), October 2026. Tokens live in `src/styles/tokens.css`;
shared components in `src/styles/global.css` and `src/components/`.
If a new page needs something these rules do not cover, add it here first.

## 1. Brand (never change)

| Element | Value | Where it is used |
|---|---|---|
| Wordmark | Script "Dhiren." (Pacifico, as SVG paths in `Brand.astro`) | Header, footer, share images |
| Logo navy | `#0e1b2e` (`--ink-strong`, `--navy-900`) | Headings, the homepage band, footer, Odoo core in diagrams |
| Main blue | `#2f7df6` (`--accent`) | Lines, marks, the world map, big blue text |
| Blue for text and buttons | `#1e63d6` (`--accent-strong`) | Links and button fills (5.5:1 with white) |
| Logo dot | blue-to-teal gradient, teal `#12b5c9` | The logo dot and the full stop of the homepage title. Nowhere else. |

These match the visiting card, the email footer and the LinkedIn banner.

## 2. Colour

- Pages are light: `--bg` `#fafbfc`, white panels, `--bg-subtle` for alternate bands.
- Navy bands are rare and deliberate: homepage hero, the "Global delivery" band, the footer.
  One navy band in the middle of a long page is fine; never two in a row.
- One accent only (blue). Green means "live / available" and nothing else.
  Amber/orange is only for "in progress" or a warning.
- No gradients except the logo dot. No glows, no grid backgrounds, no glass.

## 3. Type

| Role | Font | Notes |
|---|---|---|
| Headings (H1, H2, H3) | Space Grotesk 600 | Tight letter-spacing. One H1 size site-wide (`--text-4xl`, about 60px max). |
| Body, quotes, buttons | Inter | Running text max ~68 characters per line. Quotes are Inter, never the heading font. |
| Data labels | JetBrains Mono, uppercase, 12px | Only for facts: case numbers, dates, table headings, module chips, region names. |
| Section labels ("Services", "Case studies") | Inter 600, blue (`.kicker`) | Sentence case. |

Headlines are sentence case ("What usually goes wrong, by industry"), including case-study titles.

## 4. Layout

- Container 1200px (1320px on very wide screens), side gutter at least 20px.
- Every section opens with `SectionHeader`: a thin dark rule, the blue label on the
  left (3 of 12 columns), the title and intro on the right (9 of 12).
  Content that should line up with the title uses `.after-label`.
- Lists are **ruled rows**, not boxes: a hairline between items. Inside a `.cards` grid,
  cards automatically lose their box and become ruled columns.
- Use a real box (`.card` outside `.cards`) only for forms, side panels and the apps strip.
- Vary the section shapes down a page: a table, a list of rows, a navy band, a quote.
  Never three identical sections in a row.

## 5. Components

| Component | Use |
|---|---|
| `SectionHeader` | Opening of every section |
| `CaseRow` | A case study in a list (homepage, /work/) |
| `BeforeAfter` | Top of a case study; reads `before`, `modules`, `integrations` from front matter |
| `.arch` diagram (in case-study Markdown) | System architecture; the tier with `arch-node--core` turns navy |
| `.ledger` | One row of big numbers. At most one per page, near the top. |
| `Testimonial` | LinkedIn quotes, word for word, with a link to the original |
| `CtaBand` | The closing "Next step" block on every page |
| `.status` | "Live in production" (green) or anything else (amber) |

## 6. Motion

Feedback only: hover colour, arrow nudge, FAQ open/close. Nothing waits for a scroll
to appear, nothing counts up, nothing rotates. `prefers-reduced-motion` turns the rest off.

## 7. Images and diagrams

- Real photos only (no stock). Client screenshots only with written permission and
  anonymised data.
- Prefer diagrams built from real project data (before/after, architecture) over pictures.
- The world map is generated from `src/data/delivery.json` by `npm run map`.
- Share images (Open Graph) are generated by `npm run og` in the same flat navy style.

## 8. Writing

Plain English, short sentences, first person. Few em dashes. No "not X, but Y" lines,
no "leverage / seamless / unlock / journey". Every number must be true and must say
what it counts. One source of truth for facts: `src/data/facts.ts`.

## 9. Speed and search

- Static pages, almost no JavaScript (only the FAQ, tabs and mobile menu).
- Hero image in AVIF/WebP with `fetchpriority="high"`; everything below the fold is lazy.
- Every internal link ends in `/`. Keep URLs stable; if one must change, add a 301 in `astro.config.mjs`.
- `public/llms.txt` summarises the site for AI assistants. Update it when services or case studies change.
- Staging builds (`npm run build:stage`) are noindex and untracked. See `docs/STAGING.md`.
